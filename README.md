# TallyLights

Сервер tally-индикации для тэли-бокса **AVMATRIX TS3019** по COM-порту (протокол
**Firmata**, как у vMix). Источник состояния — пульт **Blackmagic ATEM** напрямую по
сети **или** ручное управление по HTTP (например, из Bitfocus Companion), с
переключением режимов и веб-админкой.

## Как это работает

- AVMATRIX TS3019 подключается по USB-C и создаёт виртуальный COM-порт, внутри
  эмулируя Arduino со StandardFirmata. Сервер шлёт в этот порт Firmata-команды,
  переключая для каждой лампы `ActivePIN` (эфир/красный) и `PreviewPIN` (превью/зелёный).
- В режиме `atem` сервер читает tally у пульта по UDP (порт 9910, библиотека
  `atem-connection`). В режиме `manual` лампами управляют HTTP-запросы.
- Активен всегда **один** режим — только он управляет лампами.

## Требования

- Node.js ≥ 18.
- Windows (целевая платформа). Зависимости `serialport` и `firmata` используют
  нативные биндинги — для их сборки нужны **Visual Studio Build Tools** (C++),
  либо версия Node с готовыми prebuild-бинарниками. Без рабочих биндингов сервер
  не откроет реальный COM-порт (тесты при этом проходят — они используют фейки).

## Установка и запуск

```bash
npm install
cp config.example.json config.json   # и отредактируйте под себя
npm start
```

Админка: `http://localhost:<http.port>` (по умолчанию `8080`).

## Конфигурация (`config.json`)

| Поле | Назначение |
|------|-----------|
| `comPort` | COM-порт тэли-бокса (см. Диспетчер устройств), напр. `"COM5"` |
| `baudRate` | Скорость; для StandardFirmata по умолчанию `57600` |
| `atem.ip` / `atem.enabled` | IP пульта ATEM и включён ли источник ATEM |
| `http.port` / `http.enabled` | Порт HTTP-сервера и включён ли он |
| `defaultMode` | Режим при старте: `atem` или `manual` |
| `onAtemDisconnect` | При потере ATEM: `hold` (держать) или `clear` (погасить) |
| `lamps[]` | Карта ламп: `{ id, atemInput, previewPin, activePin }` |

**Пины** (`previewPin`/`activePin`) скопируйте из своей текущей настройки
**vMix → Settings → Tally Lights** для этого же бокса — там это `PreviewPIN`/`ActivePIN`.

`config.json` не хранится в git (только `config.example.json`). Файл создаётся из
примера при первом запуске, если отсутствует.

## HTTP API (для Companion)

Ручной tally работает только в режиме `manual` (иначе `409`):

| Метод/маршрут | Действие |
|---------------|----------|
| `POST /program/:input` | вход в эфир |
| `POST /preview/:input` | вход в превью |
| `POST /off/:input` | погасить вход |
| `POST /clear` | погасить всё |
| `POST /mode/:mode` | сменить режим (`atem`\|`manual`) |
| `GET /status` | режим, связь ATEM/COM, состояние ламп |
| `GET /events` | SSE-поток статуса (для админки) |

Админ-API: `GET/PUT /api/config`, `GET /api/ports`, `GET /api/atem/scan`,
`POST /api/test/lamp/:id?color=program|preview`.

## Применение настроек (hybrid)

Сохранение в админке (`PUT /api/config`) применяет **на лету** карту ламп и
`onAtemDisconnect`. Смена `comPort`, `baudRate`, `atem.ip` или `http.port` требует
**перезапуска** — админка покажет, какие поля этого ждут.

## Тесты

```bash
npm test
```

Вся аппаратная часть (serial, ATEM, UDP) инжектируется, поэтому тесты проходят без
нативных биндингов и реального железа.

## Ограничения v1

- **Нет авто-реконнекта COM-порта.** Если порт отвалится во время работы,
  `GET /status` покажет `com: false`, но переоткрытие не делается автоматически —
  перезапустите сервер для восстановления связи с боксом.
- **«Тест лампы» — кратковременный импульс** (~1 c), после чего лампа возвращается
  к реальному состоянию.
- Аутентификации у админки нет — рассчитано на доверенную локальную сеть.
